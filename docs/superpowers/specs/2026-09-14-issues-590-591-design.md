# Issues #590 and #591 Design

## Goal

Fix board-outline detection for raw EasyEDA line-only polyline sources (#590) and make `easyeda_pcb_route_path_plan` use one explicit, live-compatible PCB coordinate contract (#591).

## #590: raw board-outline polyline fallback

When both polygon discretizers are unavailable, accept EasyEDA polygon sources that begin with an `(x, y)` vertex and then use the `L` command followed by one or more coordinate pairs. Parse the entire source before mutating the bounding box so malformed or unsupported commands fail closed. Continue to reject arc/unknown raw commands rather than under-estimating their extrema. Existing rectangle and circle fallbacks stay unchanged.

The regression fixture is the issue's live L-shaped source. Expected bbox is approximately 80.0590 mm x 50.0000 mm and `hasOutline: true`.

## #591: route-path coordinate contract

Route planning uses EasyEDA native PCB coordinates (mil) for geometry:

- `waypoints`: native PCB `x/y` in mil, preserving the active board's origin and Y direction.
- `board`: native PCB bbox `{ minX, maxX, minY, maxY }` in mil.
- `keepouts`: native PCB rectangles `{ x, y, width, height }` in mil.
- `widthMm`, `minWidthMm`, and `maxLengthMm`: physical constraints in millimetres.

The planner performs board and keepout checks in native mil coordinates, converts route length from mil to mm for `pathLengthMm`, and converts `widthMm` from mm to mil only at the `pcb.addTrack` operation boundary. Waypoint coordinates are passed through unchanged.

The route tool gets `confirmationPolicy: 'apply-mode'`, so preview does not need `confirmWrite`, while apply remains confirmation-gated. Route-specific schemas document units and do not change the grouped-placement mm contract.

Because the route `board`/`keepouts` input shape changes, the route tool metadata version is bumped to 2.0.0.
